# IC 元件管理

面向家庭工作台的电子元器件库存系统。Node.js 后端 + 中文 Web 前端，数据库位于服务器。Windows 工作机只需浏览器，不需要安装客户端。

## 功能

- 录入型号、立创编号、参数、封装、分类、厂家、位置、单价、备注及全新/拆机可用/待检测状态。
- 内部编号可手动填写，留空自动生成 `IC-000001`；可按型号、编号、库位、参数和二维码内容搜索，排序、筛选及分页。
- 单个与表格批量入库、出库、盘点，保留变动前后数量与项目关联；自动防止负库存、重复扣料与整批导入一半成功。
- 嘉立创 EDA BOM 支持 CSV、TSV、TXT、XLSX、XLS，中英文表头、UTF-16 制表符、UTF-8/GB18030 文本、多工作表与列映射。
- BOM 按内部编号、立创号、精确型号与封装查库存；多候选及冲突需人工确认。待检测元件不用于 BOM 领料；参数近似不会自动作为替代料。
- 设置制作板数和备料百分比，相同元件多行累计分配，计算最大可做板数，导出采购缺口与完整对比表。
- 整单足量领料，或明确确认仅领现有数量；每份 BOM 只领料一次，保存领料时的缺口快照。
- 批量二维码标签及 A4 打印裁切，完整 JSON 备份与恢复，恢复前自动保存当前数据。

## Windows 快速运行

1. 在服务器安装 **Node.js 24 LTS** 或更高版本。
2. 从 [GitHub Releases](https://github.com/lama684/IC-Inventory/releases/latest) 下载 `IC-Inventory-v1.0.0-windows.zip`，解压到服务器，例如 `D:\Apps\IC-Inventory`。部署包已含运行依赖，可直接启动。若从源码目录部署，则先使用 `npm ci` 或 `pnpm install --frozen-lockfile` 安装依赖；已提供锁文件。
3. 在项目目录执行：

```powershell
node backend/server.mjs
```

服务器浏览器打开 `http://localhost:3210`。工作机打开 `http://服务器局域网IP:3210`，例如 `http://192.168.1.20:3210`。默认监听 `0.0.0.0:3210`，启动会自动建立空数据库。没有任何演示数据写入正式库存。

可以双击根目录 `启动.cmd`，或指定端口和数据目录：

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\start.ps1 -Port 3210 -DataDir D:\IC-Inventory-Data
```

若工作机无法访问，在家庭服务器的管理员终端为家庭专用网络添加规则：

```powershell
New-NetFirewallRule -DisplayName 'IC Inventory' -Direction Inbound -Action Allow -Protocol TCP -LocalPort 3210 -Profile Private
```

此版本按家庭局域网单人使用设计，无登录功能。不要把此端口转发到公网。

## 软件使用说明（中文）

### 1. 首次启动

1. 双击根目录的 `启动.cmd`，或在项目目录执行 `node backend/server.mjs`。
2. 浏览器打开 `http://localhost:3210`。局域网其他电脑使用 `http://服务器IP:3210`。
3. 首次启动会自动创建空数据库，不会写入演示元件。正式数据默认保存在 `data/inventory.sqlite`。
4. 页面左下角显示“已连接”后再开始录入。若无法访问，先确认服务窗口没有报错、服务器IP正确且防火墙允许TCP 3210端口。

### 2. 录入和维护库存

1. 打开“元件库存”，点击“录入元件”。型号为必填项；建议同时填写封装、参数、立创编号、库位和最低库存。
2. 内部编号留空时自动生成 `IC-000001` 形式的编号；已有自定义编号也可直接填写。
3. 同一种元件再次采购时，在元件详情中选择“入库”，填写本次新增数量，不要重复新建型号。
4. 焊接或借用元件时选择“出库”；盘点发现数量不一致时选择“盘点”并填写实际数量。每次操作都会记录变动前数量、变动值和结余。
5. 拆机元件未检测前选择“待检测”，确认可用后再改为“拆机可用”。零库存元件可以归档，历史流水不会删除。

### 3. 批量入库

1. 在“元件库存”点击“批量入库”，选择 CSV、TSV、TXT、XLSX 或 XLS 文件，也可以直接粘贴带表头的 Excel 内容。
2. 在预览页核对列映射，尤其是型号、封装、内部编号和数量。
3. 数量列表示“本次新增数量”，会累加到已有库存，不是覆盖现有库存。整库迁移不要使用批量入库，应使用完整 JSON 备份恢复。

### 4. BOM 查缺和领料

1. 从嘉立创 EDA 导出包含型号、封装、数量、立创号和位号的 BOM。
2. 打开“BOM 查缺”，导入文件并核对列映射，填写制作板数和备料比例。
3. 检查每一行的匹配结果。多候选、型号冲突或封装冲突必须人工确认；软件不会把近似参数自动当作替代料。
4. 使用“导出采购缺口”生成待采购清单。采购并入库后，点击“重新计算”。
5. 实际取料时点击“确认领料”。库存不足时，只有明确勾选“只领取现有数量”才会部分扣料；同一份 BOM 不能重复领料。

### 5. 搜索、标签和流水

- 搜索框支持型号、内部编号、立创编号、参数、库位和二维码内容。
- 选中元件后点击“打印标签”生成A4标签；在“数据与备份”中填写服务器访问地址，可让二维码直接打开元件页面。
- “出入库流水”可按关键字和操作类型查询，并可导出完整记录。

### 6. 备份和恢复

1. 定期进入“数据与备份”，点击“下载完整备份”，把 JSON 文件保存到服务器之外的可信位置。
2. 恢复时选择备份文件，核对备份时间和记录数量，再按页面提示输入确认文字。
3. 恢复会替换当前库存、流水和 BOM；系统会先自动保存一份恢复前备份。
4. 服务运行时不要只复制 SQLite 主文件，因为 WAL 文件可能仍包含新数据。

### 7. 演示和问题排查

- 执行 `node scripts/demo.mjs` 可使用独立演示库，访问 `http://localhost:3211`；演示数据不会进入正式库存。
- 启动失败时先执行 `node --version`，确认版本不低于24，再从源码目录执行 `npm ci` 后重试。
- 页面显示断开时检查服务进程、端口占用和防火墙；不要把无登录保护的服务暴露到公网。
- 开机自动运行、数据目录迁移及卸载方法见下节说明。

## 开机自动运行（家庭服务器）

先确认手动运行成功，停止手动服务；然后以管理员身份在项目目录执行：

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\install-startup.ps1 -Port 3210
```

注册 `IC-Inventory` 开机计划任务并启动，隐藏窗口、退出后最多重试三次。默认由本机 SYSTEM 运行，绝对路径记录当前 Node 与目录，所以移动目录或更换 Node 安装位置后应重新注册；数据目录应在本地磁盘，不能使用映射网络盘。输出写入数据目录 `service.log`，需自行定期整理日志。

```powershell
Get-ScheduledTask -TaskName IC-Inventory
powershell -ExecutionPolicy Bypass -File .\scripts\uninstall-startup.ps1
```

注册脚本已提供，开发机没有自动注册开机任务或修改防火墙；真实服务器重启恢复尚需验收。

## 推荐使用流程

1. 将实购元件录入，记录实际数量和库位；后续再买同种元件直接入库，避免重复建立型号。
2. 在设计阶段先手动搜索库存；拆机元件检测完成后标记为“拆机可用”，未检测保持“待检测”。
3. 嘉立创 EDA 导出包含型号、封装、数量、立创号和位号的 BOM，进入 BOM 查缺上传。不同版本字段可能有差异，可用列映射调整。
4. 输入板数与备料比例，重新计算，人工检查未匹配、多候选和封装冲突；只有确认适用后才手动选替代料。
5. 导出采购缺口，采购后入库，再刷新 BOM；焊接取料时确认领料，查询流水追溯。
6. 数据与备份中填写家庭服务器地址，打印带访问链接的二维码；留空生成 `ICINV:元件ID`，扫码枪可直接录入搜索框。

批量入库的数量是**本次新增数量**，不会覆盖现有库存；库存 CSV 导出若再次导入会累计入库。迁移整库应使用完整 JSON 备份恢复。归档只允许零库存元件，隐藏清单并保留历史。

标签默认为 80 × 32 mm，适合 A4 打印裁切；专用标签机的纸宽、页边距、驱动和二维码手机扫码效果需用实际设备校验。移动服务器时建议保持固定 IP 或局域网域名，旧二维码链接不会自动更改。

## 数据和验证

- 正式数据默认在 `data/inventory.sqlite`，环境变量 `DATA_DIR` 可覆盖；`PORT`、`HOST` 可调整监听。
- 运行中使用网页“下载完整备份”；不要只复制正在使用的 SQLite 主文件，WAL 可能仍含新数据。停服务后可完整复制数据目录。
- 恢复前备份位于 `data/backups/`。JSON 备份包含全部业务数据，保存到个人可信目录。
- 执行 `node --test tests/*.test.mjs` 验证核心和 HTTP 闭环；21/21 本机及全新依赖目录通过，夹具为合成数据。详情见 [验证记录](docs/验证记录.md)。
- `node scripts/demo.mjs` 启动单独演示库，访问 `http://localhost:3211`；演示数据和测试操作位于 `test-results/demo-data`，不影响正式库存。
- 导入样例与空库存模板见 [examples](examples/README.md)，样例不是实购物料。
- 接口与数量约束见 [数据契约](contracts/README.md)；模块见 [后端](backend/README.md)、[前端](frontend/README.md)、[测试](tests/README.md)。
